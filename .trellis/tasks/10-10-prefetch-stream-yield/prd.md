# 预取流式化与让路（v0.3.2）

> 设计见 `design.md`，执行见 `implement.md`。父任务：`10-09-playback-startup-boost`。

## Goal

把首触预取从「8×4MB 串行逐块」改为「**单条大流 + 流式切片**」，并在客户端活跃时**让路**——
慢线路上预取 26–30s → 8–12s，**块 0 就绪提前到 2–3 秒级**（用户秒点播放也能有前缀可用）；
顺带修掉网关预热的超时假告警。

## Background（2026-10-10 用户实测日志）

- E01–E04 每集预取 26–30s：~10 次独立请求（每次付 Google ~1s 固有初始化）+ 小块低效（~1.3MB/s vs 大流 5–12MB/s）；
- 用户秒点播放（预热后 2s 即点）：只有块 0 可用 → E02 起播 ~8s；
- 预热 WARN `context deadline exceeded` 为假告警（触发已送达）。

## Requirements

- **N1** 头预取改单条流：一次 `Range: bytes=0-(head-1)`，边收边按块切片、**凑满即入缓存**；206/起点校验与 401/403 重试语义保留；新增「首块就绪」日志。
- **N2** 让路：同文件有客户端请求在途时预取暂停（500ms 轮询），空闲自动继续；不设硬上限（文档记录）。
- **N3** 断点续取：触发条件改为「期望块集（头块+尾块）有缺失且无在途预取」，只取缺失部分（连续缺失一条流）。
- **N4** 网关预热修复：响应体不读直接关；超时分级——未送达=WARN，送达后=INFO「已触发」。
- **N5** 零协议/零缓存结构变更；字节一致性不回归；随 v0.3.2 发布。

## Acceptance Criteria

- [ ] **A1** 单测：块 0 早熟（慢速滴流下先于流结束就绪）、让路（客户端活跃期无新字节落块，结束后恢复）、续取（中断后仅补缺失块、上游请求数精确）、短读/EOF/200 忽略 Range 边界；**字节一致性矩阵全绿**。
- [ ] **A2** 本机 e2e（mockmaster + 慢速假上游）：请求数 10→2 量级、块 0 就绪耗时对比记录。
- [ ] **A3** 真链（发布后）：同场景复测——秒点播放起播 ≤ 5s；正常浏览节奏接近秒开。

## Out of Scope

- 流内自动重连（续取覆盖）；让路硬上限；缓存结构/协议的任何变更。
