# 混合服务前缀先行（写前缀不等上游头）

> 设计见 `design.md`，执行见 `implement.md`。父任务：`10-09-playback-startup-boost`。

## Goal

混合服务态把「先写本地前缀」提前到上游校验之前——播放器首读 `bytes=0-` 的 TTFB 从「等上游头」（实测 1.6–5.8s）降到 RTT 地板（好线路 ~0.4s）。

## Requirements

- **N1** 新顺序：前缀命中 → **立即**写 `206` + 缓存前缀 + Flush → 再打开上游 `[start+n, end]` 续传（206/区间回声/身份一致校验全部保留）。
- **N2** 权衡明确化：上游失败或校验不过 → WARN + 关闭连接（**不再"整体回退"**；连接关闭等价网络中断，客户端自愈重试）。完整回退只保留给「前缀为空」的路径。
- **N3** 字节一致性不变：正常路径逐字节一致；全命中/未命中两态不变。
- **N4** 随 v0.3.1 发布（与 IPv6 任务同一版本）。

## Acceptance Criteria

- [x] **A1** 既有字节一致性矩阵全绿；两个"回退"用例改为「前缀已写 + 连接关闭 + WARN」断言（并验证修前会失败）；新增「上游响应头被扣住时前缀仍先到达」的 TTFB 用例。
- [x] **A2** `go test -race ./...`、gofmt、vet 全绿；签名/302/503/416/HEAD/e2e 矩阵不回归。
- [x] **A3** 真链（升级 v0.3.1 后）：NAS 实测 `bytes=0-` 首读 TTFB 0.359s、偏移重启 0.381s（目标 ≤0.6s ✓，对照 v0.3.0：3.27s / 2.41s）；全部探测达 RTT 地板。

## Out of Scope

- 未命中（无前缀）路径的回退语义（保持现状）。
