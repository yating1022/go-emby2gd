# hub v0.4.1 修复：回退换链 + 后缀区间

> 父任务：`10-10-cache-hub-center`。真链演练（2026-10-10）发现的两处小而关键的健壮性修复，随 v0.4.1 发布。

## Background（演练证据）

- **F1 回退失效（必修）**：节点把 master 下发的 hub URL 缓存在本地链接缓存里（有效期随面板直链 ~1h）。hub 停机时节点"连接上游失败（connection refused）"直接 502——**不会重新换链**（现语义只在 401/403 换链），master 侧的回退决策无人触发 → hub 故障最长 ~1h 的播放中断窗口。实测：停 hub 后探测 502（connection refused），master 无任何新的 download-link 请求。
- **F2 后缀区间（可廉价消除）**：`Range: bytes=-N` 全链不支持（节点与 hub 的 parseByteRange 均明确拒绝）→ hub 落到上游 Google 兜底 → 恰逢 Twon→googleapis 烂路 → 30s 卡死 → 节点 30s 响应头超时 → 502。真实播放器（iPhone/Lenna 实测）不发后缀形态、产能影响为零，但 hub 已知 size、可解析为 `[size-N, size-1]` 并从缓存服务。
- 附带实测（背景数据）：hub→Google 填充 ~9MB/s（好路由时）；重启后磁盘块复用正常（cached 区段 206 本地供流）；R1 窗口（重启后未缓存区段 409 not_warmed 直达客户端）按设计如实记录，≤30min 自愈——**不在本任务修复**。

## Requirements

- **N1（节点侧）**：上游"连接级失败"（dial / connection refused / 网络不可达等**无 HTTP 响应**类错误）→ 复用既有 Refresh 语义**换链一次、重试一次**；仍失败按现状 502。**仅连接级失败触发**（超时不触发，避免双倍等待）；日志与 401/403 路径同规范（不打印签名/密钥）。
- **N2（hub 侧）**：hub `/f/` 支持后缀区间 `bytes=-N`：已知 size 时解析为 `[size-N, size-1]`（N≥size → 全文件；N=0 → 按非法/416 语义走上游）；从三态服务（可缓存命中即本地供流）；size 未知维持现状（透传上游）。节点侧零改动（后缀原样透传给 hub）。
- **N3**：均带测试——连接拒绝→换链重试的**请求计数**断言；后缀边界矩阵（N<size / N≥size / N=0 / 常规与 open-ended 不回归）；node 模式与既有语义零回归。
- **N4**：随 **v0.4.1** 发布；hub 与四节点均升级；重跑演练（hub 停机→回退生效；后缀探测→缓存命中）。

## Acceptance Criteria

- [ ] **A1 单测**：连接级失败换链一次+重试一次的请求数断言；后缀区间边界矩阵；既有测试全绿、`-race`、`-count=3` 无 flake。
- [ ] **A2 真链**：停 hub → 探测未缓存区段 → 经由换链回退到 Google 直链**成功**（不再 502）；恢复 hub。
- [ ] **A3 真链**：后缀探测 → hub 缓存命中本地供流（毫秒级），不再 30s。
- [ ] **A4 零回归**：node 模式对照基线（5 个既有失败包对照式口径）；不 commit。

## Out of Scope

- R1 窗口缓解（master 探测 hub 重启 / 缩短标记）；超时类失败的换链重试；node 侧后缀直服务（hub 已覆盖该路径）。
