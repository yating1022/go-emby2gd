# agent 读前缓存（首触预取头尾 + 命中服务）

> 父任务：`10-09-playback-startup-boost`。设计见 `design.md`，执行见 `implement.md`。
> **2026-10-09 用户决策：不做"路过 tee"**——滑动窗口相对文件太小、收益只覆盖极小众的「回看」场景，
> 且会把其它文件的头尾挤出缓存；与本项目「透传」定位不符。**缓存只含每文件的首触预取块**。

## Goal

让「起播探测序列」中**除第一次以外的所有请求都变成节点本地命中**（首字节 <100ms）；第一次请求也只需付一次上游延迟。目标效果：无预热时起播 十几秒 → 2–4 秒。

## Requirements

- **N1 首触预取**：某文件第一次被请求时，后台异步预取**头部 32MB + 尾部 4MB**（可配置）；**不阻塞**当前客户端请求。
- **N2 纯透传原则**：未命中的请求按现状透传，**不缓存任何路过字节**；缓存内容 = 且仅 = 首触预取块（约 36MB/文件）。
- **N3 服务三态**：范围完整命中 → **纯本地**服务；前缀部分命中且请求延伸 → **混合**（本地前缀即刻写出 + 上游续传，总耗时不变）；未命中 → 现状纯透传。
- **N4 一致性**：块按 `(file_id, etag, 块号)` 存储；ETag 变化即整文件失效；**缓存服务与上游服务输出逐字节一致**（测试钉死）。
- **N5 有界**：内存 LRU（`CACHE_BUDGET_MB` 默认 256，0=关闭）；预算满按块淘汰（≈7 部片的头尾）；**关闭时行为与 v0.2 逐字节一致**。
- **N6 协议零变更**：对客户端/对 master 的端点、签名、状态码、响应头白名单语义全不动。
- **N7 并发安全**：预取单飞；全量 `go test -race` 通过；任何日志不打印令牌/签名。

## Acceptance Criteria

- [ ] **A1** 单测：块数学/LRU 淘汰/三态服务/ETag 失效/混合模式上游失败回退；**同一 Range 在"缓存开"与"缓存关"两模式下响应 sha256 相等**。
- [ ] **A2** 假上游集成测试（httptest 模拟 Google）：首请求触发预取 → 第二个尾部请求零上游命中（本地服务）；上游请求计数断言。
- [ ] **A3** `go test -race ./...` 全绿；既有签名/重定向/并发矩阵测试不回归。
- [ ] **A4**（父任务 A2）真链收益：Vimess 上探测序列除首请求外全部本地命中。

## Out of Scope

- 路过 tee / 滑动窗口缓存（已决策不做，理由见文头）。
- 磁盘持久化缓存（v1 纯内存；NAS 场景另行评估）。
- 播放中途顺序读的主动 read-ahead 预取（v1 只有首触头尾预取）。
