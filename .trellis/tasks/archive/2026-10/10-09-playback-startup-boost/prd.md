# 起播加速：agent 读前缓存 + 网关预热

> 父任务：包含 2 个子任务（见「任务地图」）；子任务各自独立实现与验收，**发布/升级/端到端验收在本任务**。

## Goal

把 Emby 客户端经 agent 网络的**起播时间从十几秒降到 2–4 秒**（经详情页预热时接近秒开）；拖动与重试同样受益。

## Background（2026-10-09 实测证据链，全部已复现）

- 起播慢与**带宽/节点选择/网络延迟无关**：手机浏览器直连节点 20MB/s；同网络 NAS 实测 12MB/s、4MB 拉取 ~1.7s；节点侧字节计数证实播放期有 3–8MB/s 持续输出。
- 根因 = **「播放器起播探测序列」×「每请求 ~1.2s 固定首字节延迟」**：
  - 播放器起播会发 3–6 个独立请求（头读 `bytes=0-`、尾探 MKV cues ×2、偏移重启等）；节点侧实录见 Vimess 2026-10-09 17:54:44–17:55:03（4 个请求 / 19 秒）。
  - 每个新请求首字节固定 ~1.2s：Google `alt=media` 对每个新请求约 1s 固有初始化（实测恒定：1.03s / 1.02s / 1.01s，非冷热问题）+ 链路往返 ≈0.2s；agent 侧 TTFB 实测 1.18–1.30s。
  - 合计：探测数 × 1.2s + 请求间播放器等待 1–2s ≈ 十几秒。浏览器只发一个请求所以"很快"，两者不矛盾。
- 现有 agent 是**零缓存透传**（`agent/internal/proxy/`），每个探测都全额回源。

## Requirements

- **R1**（子任务 1）agent 加**读前缓存**：首触后台预取头 32MB + 尾 4MB（**只缓存预取块，不做路过 tee**——2026-10-09 用户决策）；**部分命中时「缓存前缀 + 上游续传」混合服务**（首字节即时、后续带宽不变）；有界内存 LRU、可配置；ETag 失配即失效。
- **R2**（子任务 2）网关加**预热**：`PlaybackInfo` 与详情页（`/users/*/items/{id}`）请求触发异步「签名 + 小 Range 打一枪」，用户点播放前缓存已热；按路径去重（TTL）、失败静默、可开关。
- **R3** 协议零变更：线协议 / 签名 / 端点形态 / 响应头语义全不动；灰度期 agent v0.2 与 v0.3 可混跑。
- **R4** 可配置可回滚：agent 新键有默认值，缓存关闭时行为与 v0.2 逐字节一致；网关预热独立开关。
- **R5** 发布与升级：agent 发 v0.3.0 走既有发布流水线（`.github/workflows/release-agent.yml`）；4 个在用节点升级；网关镜像重建（ge2o:master @ ge2o-master compose）。

## Acceptance Criteria

- [ ] **A1** 子任务各自单测/集成测试全绿；含**字节级一致性校验**（缓存服务路径与上游透传路径输出逐字节相同）。
- [ ] **A2** 端到端（NAS 模拟播放器探测序列：`0-` → 尾探 → 尾探 → 偏移重启）：首个请求后其余请求全部本地命中（agent 日志两位数毫秒级），整序列总时长 **< 3s**（基线 ~19s，附对照记录）。
- [ ] **A3** 真机（用户手机）实测：直接播放 ≤ 4s；经详情页预热 ≤ 2s；一集完整观看无回归（含拖动/续播）。
- [ ] **A4** 零回归：缓存/预热任一关闭时行为与现状一致；`go test -race ./...`（agent）与网关全量测试对照基线全绿。

## Out of Scope

- zouter 从家庭网络的大流量不通（节点/线路侧问题，另行处理）。
- Google 每请求 ~1s 固有初始化（无法消除，靠减少请求数绕开）。
- 客户端播放器（Lenna）自身探测策略（不可控）。
